C14 — Preparation and transfer

Before C14

Do not install packages or run the canonical commands. Read the course introduction and record a prediction for each question.

  1. A create response is correct. Which extra observation would prove persisted follow-up state?
  2. A suite is green. Which realistic mutation would show whether the assertions are sensitive?
  3. A load report gives mean latency only. What tail and outcome data remain absent?
  4. A scanner failed to start. Is the security state pass, fail or unknown?
  5. A TLS report is a non-empty object. What makes it admissible evidence?

During C14

Label every observation SOURCE, FIXED_MODEL, JAVASCRIPT_HELPER, CANONICAL_TEST, LOOPBACK_RUNTIME, DEPLOYMENT or PLATFORM. Historical validation text remains historical.

Transfer to S14

Close the Regression Harness launched in S13 and apply Production Evidence Review to your own project. Prepare one bounded demonstration and one sampled defence claim.

claim | source | state pass/fail/unknown | owner | next action | limit

P02 is optional advanced. P04 remains a separate assessment-bank task.

Bounded Gemini critique

Ask about one sanitised readiness claim using the minimum relevant evidence excerpt. Preserve the relevant actual response, verify independently and allow UNKNOWN.

STOP

At minute 60 save an honest draft and unresolved owners. Do not publish, create a release or mark the project FINAL.

60-minute content limit. Source, model, runtime, deployment and platform evidence remain distinct.
