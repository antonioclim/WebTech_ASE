Adjust a diagnostic bound for one explicit retry

The default S14 owned child bound is 10000 ms and 1000000 output bytes. The course's neutral examples use the same defaults; optional canonical tests use 15000 ms/1000000 bytes. Internal owned capability/API children use 5000 ms/65536 bytes, while the owned HTTP operation has its own four-second deadline. Effective bounds appear in the actual reports. A timeout is a blocker to diagnose, not a passing result.

WEBTECH_CHILD_TIMEOUT_MS accepts integers 10–60000 and WEBTECH_CHILD_MAX_BYTES accepts 1024–10000000. Invalid overrides stop before child execution. Increase a bound only after identifying the affected operation and preserving the first diagnostic. The check does not automatically retry indefinitely. For one macOS/Linux invocation from S14 EN_GB:

WEBTECH_CHILD_TIMEOUT_MS=20000 node CLASSROOM_RC6/check.mjs work

For PowerShell, preserve and restore the previous process value even when the command fails:

$s14PreviousTimeout = [Environment]::GetEnvironmentVariable('WEBTECH_CHILD_TIMEOUT_MS', 'Process')

  [Environment]::SetEnvironmentVariable('WEBTECH_CHILD_TIMEOUT_MS', '20000', 'Process')
  node CLASSROOM_RC6/check.mjs work
} finally {
  [Environment]::SetEnvironmentVariable('WEBTECH_CHILD_TIMEOUT_MS', $s14PreviousTimeout, 'Process')
