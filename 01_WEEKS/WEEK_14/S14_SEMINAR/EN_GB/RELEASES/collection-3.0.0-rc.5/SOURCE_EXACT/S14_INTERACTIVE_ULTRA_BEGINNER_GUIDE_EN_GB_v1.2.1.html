Close the portfolio and defend the evidence

Prepare earlier portfolio work before S14. The seminar reviews your P01 harness and a P03 evidence table for your own project; it does not promise a full implementation from zero in 60 minutes. Work individually. Missing preparation remains incomplete and honest.

Use the first 60 minutes for technical content and the next 30 for cleanup, PDF review and authorised submission. P02 is optional and P04 is separate. No C14 Assignment is required. Tools are introduced only when a claim needs them: test runner for P01, an existing Performance or Lighthouse trace only if relevant to your own claim. No installation or general benchmark is required.

Economic context: an invoice approval can acknowledge a request before the approval is stored. Choose the cheapest boundary that observes the risk; separate operational cost from evidence strength.

Print: Ctrl+P on Windows/Linux or Cmd+P on macOS. PDF destination labels vary by browser and OS; check your actual dialog. A browser tab showing source text is not the running guide.

Evidence diagrams

One PDF and the S14 rubric

Regression Harness closure and mutation sensitivity: 3. Production Evidence Review: 3. Demonstration and sampled defence: 2. Gemini and AI-use: 1. Traceability, limitations and readable PDF: 1. Total: 10. No institutional pass threshold, deadline or PDF size limit is supplied here. Follow the authorised course settings.

Recovery and explicit limits

If storage fails, retain visible text and export JSON. If an import fails, keep the current text and check schema/version; never rename an old schema to force acceptance. If a launcher cannot open HTML, open its exact HTML target manually. If Node is absent or mismatched, stop execution and use source analysis with a label. If printing fails, use the DOCX alternative and inspect the actual saved PDF.

Windows/macOS, native Chrome/Edge/Firefox, Microsoft Word, exact runtime, Gemini live, Moodle live and owner acceptance are separate pending gates. This Phase 3 release is FINAL LOCAL for local content and packaging and grants no publication or production admission.

Protected P01 execution witness

Read the seven named contracts and adapter argument. Only regression-harness.mjs is editable. The protected oracle observes the injected systems, actual loopback requests and responses, persisted follow-up and server closure. It reruns each supplied defect and checks the corresponding failed contract independently of report booleans. Returning seven rows and four killed:true values without this activity fails.

The incomplete starter remains intentional: four objective assertion failures and one cleanup pass. The oracle is a finite local behavioural witness; it cannot authenticate authorship, an AI exchange, unrelated logs or deployment. Emergency oracle cleanup after a leaked server is recorded as failure.

Use the active-field phase map to keep evidence concise and the proposed rubric descriptors to distinguish complete, partial and no-evidence work. The numerical weights remain proposed until the teacher configures the assignment.
