0–5

Identity and release preflight

Name your project, version, runtime and evidence class. Write two falsifiable predictions before experimenting.

5–15

Close the Regression Harness

Use unit, integration and HTTP boundaries. Only regression-harness.mjs is assessed. Prepared portfolio work is required.

5–15

A response is not stored state

An invoice approval response can succeed without persistence. Which assertion observes the stored approval?

15–24

Attribute four realistic mutations

Match wrong-status, missing-persistence, leaked-internal-error and shared-state to named assertions. Keep the correct-adapter control.

15–24

Repeat and clean up

Compare two runs and record activeServers and activeRuns. A surviving fault needs interpretation.

24–36

Review the project evidence

For each of ten categories write claim, source, state, owner, next action and limit. The full reviewer program is optional.

24–36

Build and runtime have separate gates

A green build without current start/health/shutdown leaves runtime UNKNOWN. Deployment remains separate.

36–44

Demonstrate one bounded behaviour

Show the minimum witness, explain the mechanism and state what the witness cannot prove.

44–51

Defend one sampled claim

Which boundary owns this claim? What would falsify it? Which missing witness would be sufficient?

44–51

Audit Gemini rather than delegate the work

Send one sanitised claim and minimal excerpt. Preserve the actual exchange, check independently and allow UNKNOWN.

51–56

Record limitations and AI use

Acknowledge accepted and rejected assistance. Missing evidence must remain missing. Four mutation samples are not exhaustive proof.

56–60

Freeze the real evidence draft

Save the real state. At 60 stop technical content. Use the next 30 minutes for cleanup, PDF review and authorised submission.

60–90

One reviewed private PDF

Check all pages and the final paragraph. Record actual Moodle status or pending. P02 and P04 are not hidden requirements.
