One result, one correct owner

Replies may arrive out of order. An opaque request ID selects its own caller; the arrival position does not. Pending ownership exists before send. One terminal owner settles once and removes its per-request resources.

Individual core: P03 implementation in projects/p03/student/src/request-dispatcher.mjs. Required P01: your own supplied source/model annotation in the same evidence PDF. Optional P02: advanced Redis/BullMQ work with separately prepared infrastructure.

STOP at content minute 60. Save a truthful draft and unresolved work. Full P03 work is estimated at 55–65 minutes; this meeting’s 18-minute implementation segment does not promise full completion. Keep 30 meeting minutes for attendance, setup, form, Moodle and incidents.

This candidate’s source/finite model checks do not establish native browser, file://, print, exact-runtime, real WebSocket, live Gemini/Moodle or novice cohort acceptance. There is no hidden install or server start here.

Reveal: who gets the first reply?

The matching opaque ID selects the caller. r3 arriving first still belongs to caller 3. Promise.all retains its input order, which is distinct from reply-arrival order.

Reveal: can a reply happen inside send?

Yes, the immediate fake can invoke a callback before send returns. The pending owner must already exist. This witness is not a network timing guarantee.

Reveal: what does zero pending prove?

Only the stated local pending measure. A usable dispatcher can retain its subscription pair, an adapter can retain socket listeners and remote work may continue after local abort.

Glossary

Opaque ID / correlation
A token selects the request/caller without interpreting its contents as arrival position.
Pending owner / settlement
State owns resolve/reject and request resources; the terminal decision settles once.
Abort / timeout
Local refusal/cancellation; remote work cancellation needs separate protocol evidence.
Disposal / adapter
Ending one owner’s lifetime; an adapter converts socket events into the transport interface.
HTTP 202 / WebSocket
Accepted for processing, not known completed; a shared channel still needs application correlation.
TAP / draft
Deterministic test-report text; a truthful saved state with unfinished or blocked required work.
