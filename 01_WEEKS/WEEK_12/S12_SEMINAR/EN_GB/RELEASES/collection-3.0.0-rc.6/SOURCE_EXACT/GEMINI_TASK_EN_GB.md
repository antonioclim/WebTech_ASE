# S12 bounded Gemini audit — v1.2.1 FINAL_LOCAL

Use minutes 39–45 for one actual critique and 45–50 for an independent check. Gemini is a reviewer, not the final authority. This worksheet is empty guidance, not a simulated exchange.

1. Open a new browser tab using the plus button or Ctrl+T (Windows/Linux) or Cmd+T (macOS). Select the address bar, type `https://gemini.google.com` and press Enter. Wait for the page. Check the domain before entering content.
2. Start New chat if displayed; if hidden, open Menu and look for New chat. Labels can vary. Google documents that some features are available without sign-in and that school-account access can depend on institutional enablement. Use only an account and access route authorised for you. If access, age/account restrictions or a service block prevent use, record the actual block and STOP this exchange.
3. Open `GEMINI_PROMPT_EN_GB.txt` in the extracted public root. Copy the prompt, then inspect the pasted text before sending. The excerpt is explicitly schematic and minimal. Remove credentials, tokens, API keys, cookies, real personal data, private account screenshots, private code and Moodle data. Do not upload the project or complete dispatcher.
4. Paste into the prompt box. Check it contains only the bounded claim and sanitised excerpt. Select Submit once. Wait for the visible response to finish; do not send repeated requests to manufacture a preferred answer. If the page errors, record the actual message and keep a BLOCKED draft.
5. Copy only the relevant actual excerpt into `gemini_response_excerpt`. Record the actually sent prompt in `gemini_prompt`, the visible model label if available, date of your exchange and a local evidence locator. Select ACTUAL_GEMINI / OBSERVED for prompt, response and claim only when this exchange actually occurred.
6. Extract one falsifiable claim into `gemini_claim`. Label its basis Observed, Inferred or Unknown. An attractive explanation without a check is not proof.
7. Independently check that claim using your own E04/E05 fake-unit counters or a narrow source/model counterexample with a locator. Record scope, actual result and limitation in `gemini_independent_check`; set its own evidence class/outcome. Do not use the response as its own verification.
8. In `gemini_verdict_correction`, choose ACCEPTED, REJECTED, PARTIALLY ACCEPTED or UNKNOWN and justify the verdict. State a narrow correction and the remaining untested behaviour.

Verdict language examples are patterns, not model answers or execution evidence:

- ACCEPTED: the precisely scoped claim agrees with my independent check at [locator]; [limit] remains untested.
- REJECTED: my independent check at [locator] contradicts [claim]; a narrower correction is [correction].
- PARTIALLY ACCEPTED: [bounded part] is supported at [locator], while [stronger part] is contradicted or untested.
- UNKNOWN: the available check cannot establish [claim]; I can observe [limited fact] at [locator].

An unavailable exchange remains NOT_EXECUTED/BLOCKED and is printable as an honest draft. Record applicable existing teacher policy when actually supplied. This worksheet does not invent an alternative, deadline, penalty or dialogue. A source/model independent check can be honestly labelled; it does not replace the actual Gemini exchange required for normal assessed completeness.
