P01 · Parse exact note URLs without confusing draft state

A notes interface uses its URL to identify what is being viewed or edited. The special create URL must be distinguished from an existing note ID. Matching a convenient substring is insufficient: an extra path segment or invalid ID character should not accidentally select a note.

Stage 1 · Stage 2 · Stage 3 ·

Read the interface before editing

noteRoute(input) receives an object with a string path. It returns an object with kind and id. Exact /notes/new is create with null ID; /notes/<id> is read; /notes/<id>/edit is edit. IDs contain ASCII letters, digits, underscore or hyphen. Every other path returns unknown with null ID. The function receives a path string, not an entire browser URL, query object or form draft.

P02 · Publish the authoritative list only for the current refresh

P03 · Classify API, static and SPA delivery in the right order

A development server often returns the SPA page for a browser deep link. Applying that fallback to a missing JavaScript asset or an API request can return HTML where the caller expects a resource or API result. This decision function separates delivery responsibilities before any response is sent.

Stage 1 · Stage 2 · Stage 3 ·

Read the interface before editing

deliveryLane(input) receives path, method, accept (an already declared array of media-type tokens) and boolean exists. It returns one string: api, file, 404 or spa. API paths have priority; existing static files may be served; a missing /assets path is refused. A remaining SPA navigation is admitted only for GET or HEAD with text/html in the supplied token list.
