C09 — Preparation and Transfer

Before the meeting: a bounded preparation route

Set aside approximately 20–30 minutes for reading and prediction outside the meeting; this is a planning suggestion, not a measured duration or an extension of the 60-minute course. Open index.html in a newly extracted public package. Read the four-owner introduction and the source notes for examples 01–03. No installation is needed for this reading route. Do not attempt to provision missing dependencies during class.

Write a small table with four rows: URL, editable draft, confirmed resource and initial document. For each, identify an owner, an event that could change it and an observation that would not prove it changed. Use a seeded note, not private data. A local draft edit is not evidence that the API changed; a displayed location is not evidence that Back will skip the form.

Prediction 1 — location and history

Start from the declared model history [/notes, /notes/new], with the second entry selected. Predict the preceding location after successful navigation to /notes/42 when that navigation pushes. Repeat when it replaces. Write both predicted histories before running U02 and U03 in the model laboratory. After observing the model, state why its array operations are not evidence of a browser Back button.

Inspect example 01's route family. Distinguish /notes/new from a dynamic detail ID and an unknown path. The exercise is not to implement a new router or to claim that source order alone controls ranked matching. Identify the actual file and the evidence still needed from the pinned React Router application.

Prediction 2 — a simulated confirmation

Read example 02's submit handler. Underline the asynchronous operation, the title check and the navigation call. Does the function send a request, obtain a server identity or use a literal ID? Predict the blank and nonblank branches. Use F01/F02 only after writing a prediction.

Keep the phrase “simulated local confirmation” in your note. The historical README's stronger wording is not a substitute for the function body. Do not submit the model output as a Gemini exchange or claim that the model saved a resource. Actual route and server observations belong to a separately qualified application.
