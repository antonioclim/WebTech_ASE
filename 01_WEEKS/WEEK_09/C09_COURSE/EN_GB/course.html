Four owners · 00–05 minutes

One screen can hide four disagreements

The URL owns public identity. The draft holds local intent. A response confirms a resource. The server delivers the initial document. Evidence for one boundary does not settle the other three.

URL → document → route → draft → request → confirmation → history

Name an owner before proposing a fix.

Follow one synthetic note from /notes/42?filter=archived. A pasted address first asks a server for document bytes. After script loading and boot, a route parameter addresses note42; a local draft can then change without changing that address or the last confirmed title. A request sends intent, an accepted response can supply different confirmed values and navigation finally changes history. Request IDs govern publication rights; they are not a fifth resource identity.
