What you will do and why

A request can contain a plausible identity or role without having the authority to choose it. You will isolate three decisions: which principal is trusted, who may access a report and which sharing or CSRF rule applies. Keeping these decisions separate makes a security argument possible to inspect.

Before you start: Read object properties, use equality and Boolean operators, construct an object and distinguish null from an object. Earlier HTTP status-code work helps interpret P02.

Observable learning outcomes

  1. Identify which input is server-trusted and which is supplied by an untrusted requester.
  2. Translate an owner/role policy into a small decision table without widening a moderator’s permissions.
  3. Show that exact-origin sharing and a cookie-request token check answer different questions.

S11–S13 use bounded JavaScript models. They do not run Express, a queue framework, WebSocket delivery, a native Worker, a Service Worker or a cross-origin frame boundary. A classroom PASS concerns the supplied finite contract and input immutability. It does not complete the retained full application, authenticate authorship or qualify another OS/browser.

P02 — Authorisation: owner versus role

Calculate one status-code decision for a server-loaded report. “Owner” is a relationship between the principal ID and report owner ID; “moderator” and “admin” are different roles with different deletion authority. A single broad “privileged user” check would lose that distinction.

Editable target: CLASSROOM_RC6/student/p02.mjs
Exported function: reportPermission(input)

Read the input and output contract

Input fieldMeaning
actionLower-case read or delete for the stated contract.
principalAlready trusted identity {id, role}, or null for unauthenticated.
reportServer-loaded {id, ownerId}, or null if missing.
body (if supplied)Requester data. Claimed roles or ownership do not grant authority.

Return value: One number: 200 for permitted READ, 204 for permitted DELETE, 401 for unauthenticated, 404 for a missing report or unrelated READ and 403 for unrelated DELETE. These are returned numbers, not emitted HTTP responses.

The no-principal row is evaluated before ownership. The missing-report row applies after the request is authenticated. Do not invent a new action or error-loading contract from this table.
