# S06 offline form schema and migration

The v1.2.0 form is a derived successor of the supplied v1.1.0 evidence form. It keeps all 52 historical identifiers and their relative order across the seven sections. The historical 18 core and 34 final fields remain; eight core and three final fields are added, giving 26 core and 37 final fields, 63 total. The schema has a blank default for every text field and false for the declaration. No measured environment, date, prediction or observation is prefilled.

New core identifiers: evidence_date, seminar_id, kit_version, package_id, client_version, prediction_b, prediction_recorded_at and exit_ticket. New final identifiers: gemini_classification, counterexample and export_inspection. The legacy kits field remains a separate historical combined-identity field. Current date, seminar ID, kit version and PACKAGE_ID are distinct. PACKAGE_ID is not the process PID.

The current form imports its own v1.2.0 schema. A v1.1.0 draft is accepted only after explicit migration consent. All 52 values are retained verbatim except that declaration is always reset false. The eleven additions are left blank and listed in migration provenance. In particular prediction_b, prediction_recorded_at and current identity fields are not inferred from old observations. Imported text does not establish that a prediction preceded execution. Any import is marked unverified and switches local autosave off.

Unknown envelope properties or fields, missing fields, unsupported versions, invalid field types/selections, oversized values, malformed JSON and imports over 2,000,000 UTF-8 bytes are rejected before population. A rejected import retains current fields. The current draft should be exported before a replacement import. Every import resets the declaration.

The historical filename token GivenName maps semantically to Firstname through the retained ID given. Current exports suggest TW2026_S06_GROUP_Surname_Firstname.pdf. Old source records remain labelled with their old version; migration does not retroactively rename evidence.

Check core draft allows honest pending or blocked observations. Check final fields requires every field and the standard actual evidence labels/references, observed lifecycle boundary, actual Gemini state and renewed declaration, or a separately obtained teacher decision reference with scope. Structural validation cannot authenticate the text or grant approval. Every successful state explicitly ends NOT_VERIFIED. Unknown Gemini verdicts are allowed when justified; an actual interaction and independent check still belong to the standard route.

The standalone HTML contains inline schema, validation core, UI and CSS. It makes no network request and needs no server. The separate assets are maintained source copies. Optional browser storage may fail or differ under file://; JSON export is the portable private backup. Draft JSON is not a Moodle upload. Confirm the exported file really saved.

Print builds a fresh plain-text snapshot of every field and declaration. Long textarea values become paragraphs with preserved line breaks, wrapping, visible overflow and automatic page breaks. Actual browser/PDF printing still needs native observation; static CSS and supplementary synthetic checks are not proof of final pagination. Inspect every saved PDF before submission. Use the DOCX route if needed; screenshots are not mandatory.
