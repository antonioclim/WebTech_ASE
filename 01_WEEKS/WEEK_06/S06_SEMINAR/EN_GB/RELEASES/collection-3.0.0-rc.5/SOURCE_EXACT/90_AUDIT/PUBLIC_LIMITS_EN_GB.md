# S06 v1.2.0 — public evidence and qualification limits

This student edition is a locally audited teaching edition. Distribution integrity, work-boundary conformance, form completeness and genuine application execution are separate findings. A label or a filled form does not combine them into a certification.

## What the kit identifies

The final distributed manifest and PACKAGE_ID identify a particular set of bytes. The separate archive SHA-256 identifies the ZIP bytes. A legitimate student edit of the allowed target changes the distributed identity of that working copy; preserve the original identity and use `VERIFY_WORK_RESULT` for the allowed work boundary. Never rewrite the manifest to hide an edit.

Only `02_PROJECTS/p02/src/note-query.js` is the required learner implementation target. Its baseline contents remain unimplemented in the distributed student kit. Original technical `src/`, `public/`, `tests/`, package and lockfile bytes are protected. Adapted README files are explicitly derived teaching documentation, not claimed original source copies.

## Evidence classes

- `SOURCE_REASONING`: interpretation of supplied source/contract without an execution measurement.
- `SOURCE_LINKED_MODEL`: a labelled simulation or constructed expected trace; no claim of genuine supplied-stack execution.
- `ACTUAL_ORM_SQLITE`: an actual observation of the supplied Sequelize/sqlite3 route, identified with its input and environment.
- `LOCAL_HTTP`: a measured exchange with the student's own identified localhost listener; it does not independently authenticate the implementation behind that listener.
- `BLOCKED` or `PENDING`: the actual prerequisite failure or work not yet observed.

The static expected-query page and deliberate flawed AI claim are practice artefacts. They are not student observations, actual Gemini transcripts or authorisations. A dependency version lookup does not load a native driver. A correctly ordered body does not prove the translator options or zero database calls. The short file helper crosses a same-process connection boundary and does not test crash or power-loss durability.

## Platform and owner gates

Native Windows/PowerShell 5.1, macOS, Chrome/Edge/Firefox file handling, Word, the exact teaching runtime/npm, the supplied ORM/native sqlite3 stack, SQLite CLI, DB Browser, Moodle live and owner acceptance require their own evidence. This page supplies none of those acceptances. Local compatibility/synthetic checks must retain their actual class and limits.

No launch command authorises installation, network acquisition, cloud/VM access, publication or a live Moodle mutation. The student chooses their own required coursework actions through the prepared teaching environment; the production audit itself did not perform them. Preserve real errors and save a draft when blocked.

## Version boundary

This edition derives from S06 v1.1.0 and adopts the agreed v1.2.0 layout, 60-minute route, six evidence groups, bounded reviewer task and one-PDF convention. Historical v1.1.0 observations keep their original provenance. A draft migration must be explicit, retain its source version and reset the declaration; it must not silently authenticate old evidence under a new schema.

A locally available archived S01 v6.0.1 gold was used to compare startup/guard/launcher structure. This is not a byte-parity claim for newer public S01 v6.1.0, a complete current GitHub checkout or live remote publication. The current remote state is unverified in this production phase.

One individual S06 Assignment receives `TW2026_S06_GROUP_Surname_Firstname.pdf`. No second C06 Assignment, mandatory complete P01/P03 implementation, extra ZIP submission or invented deadline is introduced.
