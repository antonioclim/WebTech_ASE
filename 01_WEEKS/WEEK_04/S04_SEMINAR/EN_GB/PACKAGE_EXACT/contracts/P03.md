# P03 — Resilient Fetch

**Optional advanced extension.** Source workload: 50–65 minutes outside the seminar. It is not required for the maximum standard mark. Edit only `optional/p03/public/fetch-policy.js`.

## Required policy for the optional exercise

Implement `fetchWithPolicy(url, options)` around the supplied `singleAttempt`. Options default to `fetchImpl=fetch`, `timeoutMs=1000` and `retries=2`, with injectable `sleep`, `createController`, `setTimer` and `clearTimer`.

Each attempt uses a fresh abort controller. Clear its timer in `finally`, before a later retry delay. A successful response returns parsed JSON. Do not retry a 4xx error or JSON parsing failure after a successful response. Retry transport rejection, abort/timeout and 5xx only within the configured budget; total attempts are `retries + 1`. Before retry N, starting at 1, await `sleep(50 * 2 ** (N - 1))`.

After exhaustion, throw `request failed after <attempts> attempts: <last message>` with the last error as `cause`. The supplied UI controller owns loading/success/error display. Keep options unchanged. Do not reuse an aborted signal or contact arbitrary external endpoints.
