S04 — Own asynchronous work, delegated events and failure decisions

v4.0.0 candidate teaching tutorial; the retained implementation folder is still named CLASSROOM_RC6. Complete all 3 projects individually. The full required route is planned for 120–165 minutes and remains unpiloted. Run the capability preflight before editing. These instructions do not award a grade or invent a deadline.

What you will learn

  • Initiate independent requests before awaiting results.
  • Resolve event ownership through the closest matching element and containing list.
  • Separate transport, HTTP and parsing failures in a finite retry policy.

Core observations use injected deferred promises and a minimal DOM interface. They are real JavaScript execution, but the injected requests are not a browser Network capture and the simulated nodes are not native browser click evidence.

P01 — Concurrent request initiation

Edit only: CLASSROOM_RC6/targets/p01.mjs. Interface: await loadSummary(fetchImpl).

Reason about the boundary

Concurrency concerns when work begins. If you await the first fetch before starting the others, the requests form a waterfall. Start all three independent operations, then own their results. An HTTP error response is still a fulfilled fetch response and needs an ok/status check.

P01-03 — Separate response policy from body parsing

Reason about the boundary

The clicked target may be a span inside a button. Delegation needs the nearest action button, then ownership by the list, then the nearest task row owned by the same list. The target’s own dataset is not an authoritative shortcut.
