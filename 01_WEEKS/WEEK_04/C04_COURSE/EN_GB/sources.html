Historical statements are not new execution evidence

The canonical JavaScript and event page retain their source mechanisms. Their contextual README files now distinguish the current launch protocol from historical validation wording. No historical statement is converted into newly executed browser evidence. In particular, canonical example 05 contains a scripted initial click and a historical headless command. Use this package’s supported launch guide instead; no browser-policy changes or headless experiments are required.

The source-order reading-list-next file points to U04 HTML/CSS. The actual teaching sequence proceeds from Week 04/U03 to Week 05/U05 Node/Express/REST because HTML/CSS was already taught in Week 02. This correction is explicit in the derived transfer document; the original is not silently edited.

Primary technical references for the current explanations

  • ECMAScript: Promise.all and PerformPromiseAll — coordination uses input indices and aggregate rejection; it supplies no operation-specific cancellation.
  • ECMAScript: Await — continuation is scheduled through promise reactions.
  • WHATWG Fetch: fetch method and Body.json() — response acquisition and body consumption are separate asynchronous boundaries.
  • WHATWG DOM: closest, contains and preventDefault — lookup, ownership and cancellation of defaults have distinct contracts.
  • Node.js: EventTarget — the neutral listener-lifecycle example has Node scope rather than browser propagation.

These references support the mechanism. Exact S04 paths, accepted action labels, http:<status> text and status interval are local contract rules in CLASSROOM_RC6/contract.json and experiments.mjs. A documentation page cannot certify your own execution or the truth of a filled record.
