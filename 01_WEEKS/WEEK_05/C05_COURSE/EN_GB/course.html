05–07 min · Node and Express

One process; different responsibilities

Node supplies the runtime and HTTP server boundary. Express provides ordered request dispatch. The repository owns resource state, not request or response objects.

Node HTTP server: socket and message lifecycle
Express application: middleware and routing
Repository: list, find, create, update and remove

Does creating an Express app prove that a server is listening?

No. Construction registers behaviour. Listening opens a socket. A readiness message must report the address actually bound by that server.

U05 §§1–3; Node [N]. Primary reference keys are linked in sources.html.
Follow one request and name each owner

Use the same synthetic creation intent throughout: POST /api/tasks with a title. The listener owns the socket and accepts the message; ordered middleware supplies parsed data; the application boundary decides which values are allowed; a service/repository owns resource state; the public mapper chooses status, headers and envelope. The response lifecycle later supplies a terminal observation. Each arrow is a responsibility, not proof that the whole chain has run. A created app has registered behaviours but no bound socket; an actual READY address is a separate listener witness. Missing Express blocks that optional source execution, not the core S05 functions.

09–12 min · Ordered dispatch

Respond or delegate deliberately

Registration order is behaviour. A fallback before static resources can hide them. A response followed by an unnecessary next() can invite a second write.

Does code after next() mean the response has finished?

No. It means delegated dispatch returned to that call site. Response completion has its own lifecycle. The shown sequence is a source-expected example trace, not a newly captured HTTP log.

12–14 min · Routing

Match the method and pathname

A collection route and a member route have different identities. A query refines the requested representation; it is not another pathname.

Does a GET handler automatically implement POST on the same path?

No. Express chooses a matching method and path. In canonical example 02 the POST handler intentionally returns 501; its unsupported DELETE reaches a 404 fallback.

22–25 min · The first rejecting layer

The supplied strict JSON parser precedes the router. A valid JSON primitive can be rejected by parser policy before field validation. Arrays can pass that parser policy and fail the application shape check.

"{}"   → parseable object; missing required field
