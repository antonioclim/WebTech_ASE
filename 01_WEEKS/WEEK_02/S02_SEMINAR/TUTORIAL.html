P01 — Responsive relationship reconstruction

Edit only: CLASSROOM_RC6/targets/styles.css. Interface: CSS relationships: .card-grid, .site-header, .card and .card-media.

Reason about the boundary

Grid determines the relationship between cards; flex determines the relationship inside a card or header. A one-track mobile grid does not imply that a card itself should use grid. The media box must keep a 16:9 width/height relationship.

Contract examples to predict before execution; these are not your observations
Input or conditionExpected contract behaviour
320 CSS-pixel viewport at normal 16px browser initial font1 grid track
768 CSS-pixel viewport at the same browser settings2 grid tracks
1280 CSS-pixel viewport at the same browser settings4 grid tracks
Breakpoints in the teaching contract40rem and 64rem; min-width media queries

Implement in stages

  1. Open CLASSROOM_RC6/targets/styles.css. Keep the supplied fixture readable and keep its links available. Read the three TODO comments before making edits because all tasks share this file.
  2. Plan the base one-track grid and two min-width breakpoint changes. The supported teaching syntax is repeat(N, minmax(0, 1fr)), with N equal to 1, 2 or 4 in the appropriate rule. Write your own rules using the named selectors.
  3. Give the header a flexible relationship and each card a vertical flexible relationship. Consider how the existing margin-top:auto on a card link relies on the card layout. Set the media aspect ratio using the declared 16/9 value.
  4. Start the supplied listener using the browser procedure. At each required viewport record display, computed track widths and the visible track count. Write the actual browser version and zoom settings.
Progressive hints — open only when needed
  1. A track that cannot shrink can force content beyond the viewport. The minmax(0, 1fr) form supplies a zero minimum for the grid track.
  2. Breakpoints expressed in rem respond to the browser initial font size. Record non-default browser font settings rather than claiming the 320/768/1280 expectation applies unchanged.

P02 — Intrinsic sizing and readable content

Edit only: CLASSROOM_RC6/targets/styles.css. Interface: CSS shrinkability: .card and .long-token.

Reason about the boundary

A grid item can retain an intrinsic minimum wider than the available track. Separately, an unbroken identifier may need an allowed wrapping opportunity. Repair both relationships. Hiding overflow only conceals the symptom and destroys evidence that the content remains readable.

Reason about the boundary

Keyboard users need to see which control owns focus. Users who request reduced motion need a change in the computed transition behaviour, not merely a comment claiming accessibility.
