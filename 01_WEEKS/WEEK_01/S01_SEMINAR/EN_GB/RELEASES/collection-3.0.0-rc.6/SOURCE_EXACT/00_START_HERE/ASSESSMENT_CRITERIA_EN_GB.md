# Student assessment criteria and supplied evidence

The seminar asks you to explain observed HTTP behaviour, implement one bounded route and independently evaluate one AI claim. A passing test is evidence about the named contract. Your explanation and evidence provenance are assessed separately. Numerical weights and deadlines come from the lecturer's approved course assessment policy; this package does not allocate new marks.

| Criterion | Strong evidence | Evidence needing improvement |
| --- | --- | --- |
| HTTP accuracy | Separates method, URL path/query, request body, response headers, status and representation. | Conflates the request and response or treats a successful fetch as proof that CSS was applied. |
| Prediction and observation | A prediction saved before the experiment is compared with an actual result and a reproducible action. | A prediction written retrospectively or only an unsupported statement that it worked. |
| Mechanism | Connects parsing, route guards and response fields to the observed output. | Restates the output without explaining the operations that caused it. |
| Independent AI verification | Selects one bounded claim, examines two counterexamples and distinguishes function execution from a static inference or HTTP exchange. | Uses the AI response itself as the only evidence or attributes a supplied claim to a real interaction. |
| Provenance and limitations | Labels personal execution, supplied traces and unexecuted work; states what the evidence cannot establish. | Presents supplied evidence as personal execution or invents a successful run. |
| Reproducibility and submission | Records relevant commands, actual ports, named test results, cleanup and one readable private PDF. | Omits the reproduction path or submits clipped/private material. |

## When execution is blocked

Supplied P01 traces can support interpretation of query, body, status and response fields. They cannot prove that your machine started a server, that your own report passes the protected tests or that CSS was applied in your browser. A static trace of the flawed function can support mechanism reasoning if labelled STATIC INFERENCE; it does not prove execution. Synthetic AI practice demonstrates critical analysis of the supplied claim; it does not prove a real Gemini interaction.

P02 implementation completion and local named-test success require a later run in the approved environment. Keep the prediction and blocker, mark the experiment NOT_EXECUTED, and request the lecturer's approved recovery route. The lecturer determines assessment treatment under the course policy. The package makes no promise of equal marks for different evidence sources and imposes no automatic penalty for honest non-execution.

## Reused code and AI assistance

This is a public teaching repository. Earlier worked code can remain accessible through its Git history even when it is removed from the current student guide. Identify any reused code or AI assistance in your evidence and follow the lecturer's published course rules. Explain your own prospective predictions, observations, mechanism and limits. Matching a known implementation alone does not establish independent understanding; the evidence record is needed to assess that understanding. Do not present an earlier public example or AI-generated answer as a personally observed result.
