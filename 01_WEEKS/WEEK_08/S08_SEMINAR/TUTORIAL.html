Three individual projects · nine source stages · pure JavaScript contract with a separate conditional React fixture player

Seminar entry · Start · One formative record · C08 lesson

P02-02 · Refuse invalid capacity before deriving

Starting state and prediction. Predict the outcome for negative, fractional and text capacity, then for capacity below the number of entries. These are invalid capacity inputs. Action and mechanism. Establish the valid region before deriving the view: capacity must be an integer, non-negative and at least the array length. Think of refusal as a normal contract result. The point is to preserve the distinction between a valid full room and an impossible over-capacity state. An overflow is not repaired by hiding attendees or clamping a negative remaining value to zero.

P02-03 · Derive the view and test full versus over-capacity

Starting state and prediction. For valid input, used plus remaining must equal capacity. Predict the object for an empty zero-capacity collection, an exactly full collection and a collection with one free seat. Zero/zero is full because no seat remains; it is not invalid. An over-capacity input belongs to the refusal region from stage 2.

Action and mechanism. Complete the derived view from the two authoritative inputs and your valid-region decision. In React, render can calculate this inexpensive view directly from props or state. Creating another state variable for remaining seats and an effect to synchronise it introduces a second owner and a possible intermediate mismatch. Derivation is calculation; effects synchronise an external relationship.

Change and observable. Run check.mjs work and your own full/not-full JSON cases with try.mjs P02. Compare every field, including the Boolean full. State the invariant for each valid result and verify that the source array stayed unchanged. This finite function check is not evidence that a React component rendered the count or that a registration service accepted a reservation.

Trap, diagnosis and recovery. A string such as "false" is truthy JavaScript data, not the required Boolean. A clamped overflow can look full but erases the error. If zero/zero fails, inspect assumptions such as capacity needing to be positive: this contract permits zero. If a number is correct only after a later effect, examine whether you unnecessarily duplicated the source in a UI design. P03-01 · Name the current publication owner

Starting state and prediction. This function receives the relevant values explicitly and does not run any effect or cleanup.

Trap, diagnosis and recovery. “The last reply to arrive wins” confuses settlement with permission. Treating B as newer because its label sorts after A also invents an ordering contract. If a stale reply is permitted, inspect which values your comparison actually uses. Restore the declared order, hold activity constant and change only the arriving identity. A null TODO is unfinished; an exception does not demonstrate refusal.

Trap, diagnosis and recovery. Checking only the ID admits work after disposal; checking only activity admits an old request. Replacing the conjunction with an alternative admits both mistakes.
