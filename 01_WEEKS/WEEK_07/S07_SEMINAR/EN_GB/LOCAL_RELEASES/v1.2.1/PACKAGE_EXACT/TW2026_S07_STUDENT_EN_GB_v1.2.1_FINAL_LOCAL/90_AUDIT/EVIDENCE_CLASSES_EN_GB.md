# Evidence classes and honest limits

Label each witness with its class, fixture, command or source path, runtime, before-state, after-state and observed or expected status. Use NOT_EXECUTED with a reason when execution is pending.

| Class | Scope |
| --- | --- |
| SOURCE_REASONING | Explanation grounded in identified source and contract text |
| SOURCE_EXPECTATION | Predicted result derived from source before execution |
| MODULE_MODEL | Newly authored model of a bounded mechanism |
| SYNTHETIC_PRACTICE | Training with labelled invented fixtures or outputs |
| GENUINE_ORM_SQLITE | Actual supplied ORM and native SQLite observation |
| LOCAL_HTTP | Actual request and response on the supplied local application |
| ACTUAL_GEMINI | An actual recorded interaction and independently checked claim |
| NATIVE_BROWSER or NATIVE_WORD | Observed behaviour in the named native interface |
| NATIVE_WINDOWS or NATIVE_MACOS | Observed behaviour on the named operating system |
| NOT_EXECUTED | Pending work with an explicit reason |

A source hash establishes byte identity. A syntax check establishes a bounded parse result. Neither proves application behaviour, native commit timing, concurrency safety, crash durability or rollback of external effects. A successful structure check does not authenticate your observations or the authority of a teacher exception.

The canonical four-method spy omits event.save and can accept undefined transaction values in a model. Use the separate five-operation witness with shared non-null identity. A sequential rollback witness remains sequential.

The local production environment has Node v24.19.0 rather than the documented v24.21.0 and has not loaded project dependencies or the native SQLite driver. Windows, macOS, browser print, Word, actual Gemini and Moodle acceptance remain external checks.
