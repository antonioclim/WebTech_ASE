Before the meeting

Read the first three handout sections and inspect the declarations in canonical/01-relationship-shapes/example.js. Do not install or run dependencies as part of this reading route. The presentation, handout and laboratory open directly from local files. Genuine examples require the separately prepared project-local stack; see guide.html.

Write three brief predictions: where ticketType belongs, which constraint prevents duplicate membership and what the lazy statement count would be for three parents. Label these SOURCE_REASONING. An archived assertion is not your executed result.

Recall Week 06’s distinction between metadata, actual ORM state and client observations. C07 adds the consistency boundary across related records. The new laboratory is a JavaScript teaching model, not a database. Opening it does not load Sequelize or a native driver.

Use the course home index.html. For the presentation select course.html; use Previous, Next or the screen selector. Arrow keys work outside interactive controls. Text size has a 40–160% range independent of browser zoom. Reading mode exposes the whole sequence and print styles include explanations. Neither a print request nor a browser download request proves that a file was saved.

Read SOURCE_NOTES.md before interpreting Example01, Example03 or Example04 README claims. Their discrepancies are preserved and explained. In particular, Example04’s cursor predicate does not follow every permitted primary ordering. The new catalogue trace is separately identified; it does not rewrite the original endpoint.

Bring no real personal dataset or credentials into the experiment. A tiny sanitised fixture makes predictions and counterexamples easier to inspect. No application installation is hidden in the 60-minute teaching plan.

After the meeting: transfer and ADR preparation

Finish any handout sections not discussed in depth. Run the fixed-snapshot catalogue model again with its duplicate-rank case and explain why the tuple rule differs from id > lastId. Do not infer a guarantee under concurrent key updates. Examine the exact source discrepancy notes rather than claiming all historical assertions have been executed.

Prepare the required ADR questions: what client operation is addressed, what identifies its resource, which related state belongs in one transaction, what is the intended effect of repetition and what alternative did you reject? Use the semester project when defined. Otherwise make the provisional course-domain choice explicit and state when to revisit it. Do not copy a generic “REST is better” conclusion.

The proposed ADR length is 300–500 words plus a compact client-effect table. This is a teaching scope rather than an original canonical word limit. The full P03 Registration API Redesign implementation is not separately compulsory. P01 is optional advanced work. P02 Transactional Booking remains the only required complete implementation in S07.

The P02 source estimates 55–65 minutes for the implementation alone. The seminar allocates 28 minutes inside its core and makes remaining work explicit. Finish outstanding work on the same project and the brief ADR before the later teacher-configured deadline. Do not fabricate a completed test or a live Gemini exchange to close the form at minute 60.
