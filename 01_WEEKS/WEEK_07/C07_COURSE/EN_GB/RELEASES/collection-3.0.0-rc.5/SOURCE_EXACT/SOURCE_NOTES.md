# C07 source notes and discrepancies

The twenty files in the five canonical example roots and the next-reading list are exact copies. They are not edited to match a preferred explanation. CANONICAL_SOURCES.json records their identities. The current guide.html is the launch route; historical README installation commands are retained as source text, not an instruction to install now.

## Example 01 — Relationship Shapes

The script creates one conference, one session and one attendee. The README describes two sessions. The nested Registration.ticketType and duplicate-membership assertion are real source content but their genuine execution remains pending.

## Example 02 — Eager-loading Query Count

The logger is cleared before each route. Four lazy statements and one eager statement are expected for three parents. A one-query result is not automatically a lower cost or a capped graph. The laboratory's count is a calculation, not SQL logging.

## Example 03 — Resource Contract

The script performs sequential PUT and DELETE membership assertions. Query-page validations described in its README do not appear in the script. Sequential create-or-update does not itself qualify arbitrary concurrent upsert. The registration contract must not be silently assigned to P02 booking POST.

## Example 04 — Pagination Stability

The original archive preserves the id-only cursor and its README discrepancy. In this new edition, canonical/04-pagination-stability uses a composite sort-key and ID cursor, validates limits and filter/sort context, and asserts complete traversal including tied keys. The separate derived/cursor-model.js remains a fixed numeric conceptual model, not the endpoint or a concurrent-update guarantee.

## Example 05 — Transaction Timeline

The failAudit flag throws before Audit.create; it does not inject a rejection from an attempted audit insert. Source assertions test rollback after the checkpoint and a later success when the genuine stack runs. They are not current execution results.
