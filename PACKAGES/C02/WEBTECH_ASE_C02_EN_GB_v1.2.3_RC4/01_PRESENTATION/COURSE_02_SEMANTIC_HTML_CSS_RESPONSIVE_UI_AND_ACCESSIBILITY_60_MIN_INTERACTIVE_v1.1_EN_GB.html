Business case · 0–5 min

The same claim, different risks

The interface may conceal a process defect even when the data looks correct.

The user must

  • understand the data
  • correct errors
  • reach the action
  • observe the result

Risks hidden by the screenshot

  • a clickable div
  • a placeholder without a label
  • status hidden by the cascade
  • a removed focus indicator

In an economic information system, loss of interface control can change the decision rather than merely the appearance.

Meaning · 5–13 min

HTML expresses structure and purpose

A native element begins with a meaning and behaviour contract that CSS cannot create retrospectively.

<main>

The main region of the document.

<button>

An action with focus and keyboard activation.

<label>

A persistent name and a larger activation target.

Deeper: ARIA

ARIA can expose necessary relationships, but it does not make the appropriate native element redundant.

CSS can change presentation; it cannot retrospectively create meaning that is missing from the document.

Native element · 5–13 min

Link, button or control?

Choose the semantic owner of the operation rather than the easiest element to style.

Scenario: the user confirms approval without leaving the page.

Counterexample: a link may trigger server-side work, but its perceived contract remains navigation.

Prefer the native element whose semantic and interaction contract matches the operation.

Forms · 13–22 min

The accessible name is not the placeholder

The label answers “what is this field?”, while the description answers “what should I know?”.

<label for="amount">Amount</label>
<input id="amount"
  inputmode="decimal"
  aria-describedby="amount-hint">
<p id="amount-hint">RON, two decimal places</p>

Distinct relationships

name Amount

description expected format

value entered data

A visible label and an accessible name may overlap, but they are not the same relationship.

Cascade · 22–32 min

The cascade selects a value

Specificity is only one stage in the process.

relevance→origin / importance→context / layer→specificity→order

Scope of the demonstration: normal author declarations, layers, specificity and source order.

Specificity does not lead the cascade; it matters only after the criteria that precede it.

Prediction · 22–32 min

Which rule wins?

A less specific rule can win when it appears in a later layer.

@layer legacy, theme;

@layer legacy {
  #claim .status { color: #9a3412; }
}
@layer theme {
  .status { color: #0f766e; }
}

Counting selectors before checking the layer can diagnose the cause in reverse.

DevTools evidence · 22–32 min

Computed styles explain the result

Inspect the winning declaration, crossed-out competitors, inheritance and the computed value.

#claim .status { color: #9a3412; } legacy
.status { color: #0f766e; } theme
computed color: rgb(15, 118, 110)

Question: which claim does this trace support and what can it not prove about contrast?

DevTools explains the observed mechanism; it does not replace testing the relevant state and context.

Reflow · 48–55 min

One column is not enough

At 320 CSS px, information and function should remain available without two-dimensional scrolling, subject to defined exceptions.

Select a state.

Reflow is behaviour across a range of states, not a conveniently selected screenshot.

Keyboard · 48–55 min

Visible focus identifies the next target

The indicator must be checked on the focused element through the real keyboard path.

Press Tab in the browser. A programmatic focus() call can aid demonstration, but it does not prove the whole path.

Focus is not decoration. It is the state that makes the next command predictable.

Preferences · 48–55 min

Motion is presentation, not function

Under prefers-reduced-motion: reduce, the action remains available while non-essential motion disappears.

Claim processed

Adapt presentation to the preference without removing information or action.

Optional extension · 60–63 min

Autopsy of an apparently correct interface

The screenshot is tidy. Six contracts are broken.

Control

An <div onclick> styled as a button.

Name

The placeholder disappears when the user types.

State

The status is hidden when it no longer fits.

Sizing

The card uses height:12rem.

Order

order:-1 moves the action visually only.

Motion

The transition remains compulsory.

Task: name the owner, evidence and limitation for each defect.

An interface may be visually coherent and contractually incoherent.

Optional extension · 63–66 min

Who killed the status?

Do not accuse specificity before inspecting every applicable declaration.

@layer base, theme, emergency;
@layer base { .status { display:inline-flex; } }
@layer theme { #claim .status { color:#0f766e; } }
@layer emergency { .status { display:none !important; } }

Trace: matched rules → winning declaration → computed style → geometry.

Computed style does not guess the culprit. It shows it for the inspected state.

Optional extension · 66–69 min

The attractive control that is not a button

cursor:pointer changes the cursor. It does not add role, focus or keyboard behaviour.

The imitation

<div class="approve" onclick="approve()">Approve</div>

Focus, Enter/Space, disabled state and naming must be rebuilt manually.

The native contract

<button type="button">Approve</button>

It starts with defined semantics and keyboard operation.

A native element does not remove testing. It removes behaviour that we would otherwise invent.
