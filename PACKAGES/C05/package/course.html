05–07 min · Node and Express

One process; different responsibilities

Node supplies the runtime and HTTP server boundary. Express provides ordered request dispatch. The repository owns resource state, not request or response objects.

Node HTTP server: socket and message lifecycle
Express application: middleware and routing
Repository: list, find, create, update and remove

Does creating an Express app prove that a server is listening?

No. Construction registers behaviour. Listening opens a socket. A readiness message must report the address actually bound by that server.

12–14 min · Routing

Match the method and pathname

A collection route and a member route have different identities. A query refines the requested representation; it is not another pathname.

GET  /api/tasks?completed=true  → collection + query
GET  /api/tasks/t-1             → member t-1
POST /api/tasks                 → creation handler
DELETE /api/tasks               → example-specific fallback

Does a GET handler automatically implement POST on the same path?

No. Express chooses a matching method and path. In canonical example 02 the POST handler intentionally returns 501; its unsupported DELETE reaches a 404 fallback.

22–25 min · The first rejecting layer

JSON syntax is not the whole boundary

The supplied strict JSON parser precedes the router. A valid JSON primitive can be rejected by parser policy before field validation. Arrays can pass that parser policy and fail the application shape check.

"{bad" → syntactic JSON failure
"null" → valid JSON; rejected by strict object/array policy
"[]"   → parseable array; invalid task body shape
"{}"   → parseable object; missing required field

25–27 min · Validate then normalise

Do not turn arbitrary data into a title

Check the value type and allowed keys before normalising. A blank string, an array and an unknown key are separate witnesses. Normalisation is not permission to change the accepted type.

typeof value === "string"   // boundary

Why can a successful JSON parse still be followed by a 400 response?

Parsing establishes a JavaScript value under parser policy. Application validation establishes the allowed fields, types and meanings. The local laboratory separates these steps using a declared teaching model.

Name the clock boundary

The canonical observer captures duration when writeHead first commits the response headers. That captured value is reused when the terminal log is written.

start: 100 ms   commit: 112 ms   finish: 135 ms
header duration = max(0, 112 − 100) = 12 ms

What does this value fail to measure?

It does not measure total elapsed time until finish, transport latency or client receipt. The supplied numbers are a controlled module-model observation; they are not network timings.
