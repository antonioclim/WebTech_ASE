00–03 min · Two timelines

Who may update this page?

A dashboard has independent data sources and a user who can act before they finish. The line after a call is not necessarily the next visible effect.

module loads → handlers are bound
user action → state transition → loading
work settles → continuation → current-owner check → final state

Predict three things separately: what starts first, what finishes first and which result may change the page.

Source order describes the synchronous segment. Settlement resumes a continuation. State ownership decides whether that continuation may still commit. A plausible final page does not reveal the path that produced it.

12–15 min · Continuation

An async call begins synchronously

Calling an async function begins its body on the current stack. Await suspends that function’s continuation. Even awaiting an already fulfilled promise does not run the continuation inline.

async function value() {
  await Promise.resolve();
  return 7;
}
const pending = value();
pending.then(number => console.log(number));

Is pending the number 7? Who observes failure?

pending is a promise. The function returns a fulfilment value later; a thrown error becomes rejection. This tiny illustrative call has no failing branch. Real acquisition needs a caller that awaits, returns or handles its rejection.

15–18 min · Worked trace

Predict all five messages

The following complete teaching trace matches the order tested in canonical example 02. Write the order before opening the explanation or running the laboratory.

const events = [];
async function run() {
  events.push("function start");
  await Promise.resolve();
  events.push("after await");
}
events.push("script start");

events.push("script end");
done.then(() => console.log(events));

Which comes first: script end or after await?

script start → function start → script end → after await → promise fulfilled. The top-level synchronous segment finishes before the queued continuation. This is a promise trace, not a measurement of browser painting.

18–21 min · Promise ownership

The caller must own the result

A catch is a policy boundary, not a decoration. A helper should preserve an informative failure; the controller that owns visible state decides how to display it.

async function readOne(load) {
  try {
    const result = await load();
    return { kind: "success", result };
  } catch (error) {
    return { kind: "error", message: String(error.message) };
  }
}

What would a missing return from readOne change for its caller?

An async function still returns a promise, but the fulfilled value may become undefined. Returning a state object is a deliberate local policy here, not the assessed Dashboard implementation.

21–24 min · Initiation

Start independent work before waiting

Sequential waiting is correct when the next input depends on the previous result. For independent sources, identify where each operation is actually called.

// Dependent: second call needs the first result.
const person = await loadPerson();
const jobs = await loadJobs(person.id);

// Independent: both calls happen before await.
const names = ["alpha", "beta"];
const pending = names.map(loadIndependent);
const results = await Promise.all(pending);

Which line starts the independent work: map or Promise.all?

The calls made by map start the operations in this example. Promise.all coordinates their results; it does not turn uncalled functions into running requests. These are labelled excerpts with application-supplied loaders.

30–33 min · Fetch boundary

A response is not an accepted status

fetch normally fulfils when an HTTP response arrives, even for a non-success status. The application classifies response.ok or the status before using the representation.

async function readJson(url, fetchImpl) {
  const response = await fetchImpl(url);
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  return response.json();
}

Does a fulfilled response with status 404 reach json in this helper?

No. The helper rejects at its HTTP-policy boundary before parsing. A transport rejection never produces response here. This small acquisition helper is not the complete assessed controller.

33–36 min · Representation

A 200 status is not a JSON guarantee

The status can be accepted while body parsing rejects. Even successful JSON parsing does not prove that the resulting data matches a domain schema.

46–48 min · Delegation

Resolve the actionable descendant

One stable ancestor can handle a changing collection. closest resolves an action; contains checks that it belongs to the intended boundary.

function actionFrom(event, list) {
  const target = event.target;
  if (!target || typeof target.closest !== "function") return null;
  const action = target.closest("[data-action]");
  return action && list.contains(action) ? action : null;
}

What should a click on list whitespace do?

It is a guarded no-op for the action. It need not become a task action merely because the listener ran. Task identity is separate from both the target tag and the listener id.
