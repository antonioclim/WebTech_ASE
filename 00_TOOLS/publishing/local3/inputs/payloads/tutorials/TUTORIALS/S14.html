What you will do and why

A returned success object can disagree with stored state, and a clean-looking review can conceal missing evidence. You will inspect a real supplied local service/repository in P01 and implement a bounded fail/unknown/pass decision in P03. There is no P02 classroom task in this seminar.

Before you start: Call an exported function, use a supplied adapter, compare object fields, inspect arrays and distinguish a failed observation from an unknown one. Earlier state and HTTP-status work helps identify what P01 actually does and does not exercise.

Observable learning outcomes

  1. Create through a supplied service and independently inspect repository persistence.
  2. Detect the supplied missing-persistence defect instead of accepting the returned object as proof.
  3. Give required failure precedence over unknown evidence and distinguish scoped model PASS from production readiness.

P01 executes the actual supplied local service and in-memory repository synchronously. It does not exercise HTTP. P03 is a bounded JavaScript evidence-decision model. A classroom PASS concerns the supplied finite contract and input immutability. It does not complete the retained full application, authenticate authorship or qualify another OS/browser.

P01 — Regression: actual persisted follow-up

The service returns a record even when a deliberately defective repository discards it. Your function must create through the supplied adapter and perform a separate repository lookup. This is an actual local service/repository call; the classroom target does not create or call an HTTP server.

Editable target: CLASSROOM_RC6/student/p01.mjs
Exported function: persistenceWitness(input, adapter)

Read the input and output contract

Input fieldMeaning
titleSynthetic title string. The supplied service trims it and requires the trimmed length to be 3–80 characters.
defectNull for ordinary operation or missing-persistence for the required mutation case.
adapter (second function argument)Module passed by both the checker and runner. It exports createChecklistSystem({defect}), whose returned system exposes service and repository.

Return value: {createdTitle, storedTitle, persisted}. createdTitle is observed from the created record; storedTitle is observed from a separate lookup, or null if absent. persisted is true only when that stored record matches the created record. The missing-persistence case must yield false. The function is synchronous in the supplied tests.

Supplied adapter operations to inspect

OperationObserved source behaviour
adapter.createChecklistSystem({defect})Create a local system with the requested synthetic defect.
system.service.create({title})Validate/trim the title, create a record and return its record object, including its ID.
system.repository.find(created.id)Independently retrieve the record by the actual created ID. Returns a clone or null.
adapter.createChecklistServer(system)Exists in the supplied adapter, but the classroom P01 tests do not call it. Do not turn this synchronous task into an HTTP harness.

P03 — Production evidence: fail/unknown/pass gate

A review must preserve failures and missing witnesses. Derive an aggregate decision from required rows: any fail wins; otherwise any unknown prevents PASS; otherwise the decision is a scoped PASS. Optional deployment remains visible without blocking this classroom gate. The function does not verify that row text is true.

Editable target: CLASSROOM_RC6/student/p03.mjs
Exported function: evidenceGate(input)

Read the input and output contract

Input fieldMeaning
rowsArray of objects with an evidence label id, lower-case state (pass/fail/unknown) and Boolean required. Supplied tests use short labels such as BUILD and AUDIT.

Return value: One upper-case string: FAIL if any required row fails; otherwise UNKNOWN if any required row is unknown; otherwise PASS for the supplied scoped inventory. Do not turn an absent witness into pass or change the rows to obtain a preferred decision.
