# Selected activity environment policy

`environment.mjs` is the canonical read-only policy used by the T01–T07 units. The byte-identical standalone carriers are listed and checked by `verify-carriers.mjs`. Run `node 00_TOOLS/runtime/verify-carriers.mjs` and `node --test 00_TOOLS/runtime/tests/environment.test.mjs` from the collection root. These tests exercise policy and delivery consistency; injected versions are not runtime qualification.

`assessEnvironment({unit, operation, cwd, command, features, usesNpm})` returns an async JSON report with `status`, `exitCode`, observed versions and executable paths, feature checks and the recheck command. `observedCwd` and `observedArgv` identify the real invoking process; `cwd`/`command` and the explicit `recheck` object describe the selected package diagnostic route. These may differ when a launcher is invoked from another directory. `ENV_OK` and `ENV_WARN` return 0; `ENV_BLOCKED` returns 2. `requireEnvironment(options)` emits the report and throws on a blocked activity. Features are `node-core` (always), `http`/`loopback-http`, `fetch`, and `sqlite`. Node-only calls do not look up npm. A missing optional companion belongs to its own operation.

The retained reference is Node `v24.21.0` and npm `11.19.0`; neither was executed in T01. Real probes were run on Node `v24.19.0`, npm `11.9.0`, Ubuntu x64. A parsed different minor, patch, major or prerelease number gives `ENV_WARN` only after indispensable probes succeed. This permissive policy authorises limited selected operations; it does not qualify a broad version interval or platform. Actual import, missing method, failed operation, tool exit, malformed output and time/output failures remain blocked.

The core probe imports the modules needed by the runners and invokes SHA-256 and `Object.hasOwn`. HTTP creates its own listener on `127.0.0.1`, an ephemeral port and its own request; sockets and listener close in `finally`. SQLite imports `node:sqlite`, checks `DatabaseSync`, `exec`, `prepare`, `close`, statement `run`, `get`, `all`, and performs an in-memory roundtrip before close. It installs no npm package. The SQLite profile is supplied for separate diagnostics. Historically, T01 changed none of S03–S14. T02 now integrates S03/S04 with node-core guards and keeps HTTP checks separate for S04 serve; T03 now integrates S05/S06; T04 now integrates S07/S08; T05 now integrates S09/S10; T06 integrates S11/S12 and T07 integrates S13/S14. These historical milestones identify source changes, not fresh executions on every later snapshot.

Limits: one HTTP attempt, 4 seconds; subprocess diagnostics, 5 seconds and 64 KiB combined output. `runBounded` accepts `timeoutMs` and `maxBytes` for explicit callers. Day0 native wrappers use 10 seconds and 64 KiB per tool; VS Code list/version have their existing 15/20-second Windows limits. The Windows helper reads both pipes concurrently and caps output; timeout kills only the process it started. There is no process-name/global cleanup. A tool that launches its own descendants is not certified by this helper; native Windows/macOS execution is still unverified.

No installation, config write, lockfile replacement, `--force`, global upgrade or ExecutionPolicy change occurs. On Windows npm-cli.js is run through the observed Node where discoverable; the Day0 native wrapper uses `npm.cmd` rather than `npm.ps1` for its explicit npm diagnostic. Other npm versions have not been qualified. In the T01 scope, C01, C02, S01, S02 and Day0 contain no npm project manifest, lockfile or `.npmrc`; their direct Node/static operations have no `engines`, `devEngines` or npm script gate to repair. The former C01/Day0 exact equality was the observed local gate; the reported two-minor npm incident was not reproduced.

The generic npm diagnostic checks the CLI and effective configuration; it does not approve installation, dependency resolution, a manifest/lockfile pair or React. npm v11 documents advisory `engines` without `engine-strict`, fatal `devEngines` by default before install/ci/run, and `npm ci` rejecting disagreement and replacing existing `node_modules`. These rules must not be applied as universal qualification to other npm majors.
