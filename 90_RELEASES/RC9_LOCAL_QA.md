## Reproduction and publication boundary

Run the strict whole-source validator and the current RC9 tests using the exact reference Node runtime. Prepare the three release assets with `resolve_classroom_rc9.py`, outside the checkout. The resolver checks the authoritative plan, source seal, authentic immutable inputs, exact scope and deterministic ZIP closure before admitting assets. Replays must be byte-identical and unexpected/conflicting outputs are refused before replacement.

The workflow remains `workflow_dispatch` only. It requires explicit preview and the exact reviewed commit SHA, fails closed on lookup errors, creates a new ref atomically and verifies its target before preparing a draft prerelease. Existing tags/releases are never overwritten by the recipe. The assistant did not dispatch, rerun or cancel Actions, create a release or create a tag. The owner alone may start the workflow after the final review phase. After actual publication, a separate reviewed navigation/status update must name RC9 as published; this source intentionally makes no premature publication claim.
